Interview questions

List vs tuple? Lists can change; tuples can't. Tuples are hashable, so they can be dictionary keys, and they suit fixed data such as Selenium locators (By.ID, "x").

What is the mutable default argument problem? Default values are created once, when the function is defined. A list default is therefore shared across calls. Use None and create the list inside.

is vs ==? == compares values; is checks whether two names point to the same object. Use is only with None.

Shallow vs deep copy? copy.copy copies the outer object but shares nested objects. copy.deepcopy copies everything. This matters when you tweak one test's payload built from a shared template.

Write find_duplicates(items). It returns each value that appears more than once, in the order it first appeared.

Show answer
def find_duplicates(items):
    seen, dupes = set(), []
    for item in items:
        if item in seen and item not in dupes:
            dupes.append(item)
        seen.add(item)
    return dupes

assert find_duplicates(["a", "b", "a", "c", "b", "a"]) == ["a", "b"]
assert find_duplicates([1, 2, 3]) == []

A set gives O(1) lookups, so this stays fast even for long lists. Interviewers like it when you mention that.

def mask_email(email):
    if email is None:
        return None
    if "@" not in email:
        raise ValueError(f"not an email: {email!r}")
    local, domain = email.split("@", 1)
    return f"{local[:1]}***@{domain}"

Classes and objects

A class is a blueprint; an object is one thing built from it. __init__ runs when an object is created, and self is that object.

class TestCase:
    def __init__(self, tc_id, title, priority="P3"):
        self.tc_id = tc_id          # instance attributes: one copy per object
        self.title = title
        self.priority = priority

    def is_blocker(self):
        return self.priority == "P1"

    def __repr__(self):             # what print() and the debugger show
        return f"TestCase({self.tc_id!r}, {self.priority})"

tc = TestCase("TC-101", "Login with valid user", "P1")
tc.is_blocker()    # True
print(tc)          # TestCase('TC-101', P1)

A fake driver, so you can practise without a browser

This class pretends to be Selenium. It records every action it receives. You'll use it to build Page Objects today, and next week you'll swap in the real driver without changing the pages.

class FakeElement:
    def __init__(self, driver, locator):
        self.driver, self.locator = driver, locator

    def click(self):
        self.driver.actions.append(("click", self.locator))

    def send_keys(self, text):
        self.driver.actions.append(("type", self.locator, text))

    @property
    def text(self):
        return self.driver.texts.get(self.locator, "")


class FakeDriver:
    def __init__(self, texts=None):
        self.actions = []
        self.texts = texts or {}
        self.current_url = ""

    def get(self, url):
        self.current_url = url
        self.actions.append(("open", url))

    def find_element(self, by, value):
        return FakeElement(self, (by, value))

The four pillars, in a framework

PillarMeaningWhere it appears in a test framework
EncapsulationKeep data and the code that uses it together; hide the internalsLocators are private inside each Page class; tests call login() and never touch locators
InheritanceA child class reuses and extends a parentLoginPage(BasePage) inherits open(), click(), type(), waits
PolymorphismSame method name, different behaviourEach page has is_loaded(); a driver factory returns Chrome or Firefox and tests treat them the same
AbstractionExpose what something does, not howcheckout.place_order(user) hides 15 clicks; an abstract BasePage.is_loaded() that every page must implement

Inheritance: BasePage and LoginPage

from abc import ABC, abstractmethod

class BasePage(ABC):
    BASE_URL = "https://www.saucedemo.com"      # class attribute: shared by all pages
    PATH = "/"

    def __init__(self, driver):
        self.driver = driver

    def open(self):
        self.driver.get(self.BASE_URL + self.PATH)
        return self                              # lets you chain: LoginPage(d).open().login(...)

    def click(self, locator):
        self.driver.find_element(*locator).click()

    def type(self, locator, text):
        self.driver.find_element(*locator).send_keys(text)

    def text_of(self, locator):
        return self.driver.find_element(*locator).text

    @abstractmethod
    def is_loaded(self):
        """Every page must say how to recognise itself."""


class LoginPage(BasePage):
    PATH = "/"
    _USERNAME = ("id", "user-name")             # leading underscore = private by convention
    _PASSWORD = ("id", "password")
    _SUBMIT   = ("id", "login-button")
    _ERROR    = ("css selector", "[data-test='error']")

    def login(self, username, password):
        self.type(self._USERNAME, username)
        self.type(self._PASSWORD, password)
        self.click(self._SUBMIT)

    def error_message(self):
        return self.text_of(self._ERROR)

    def is_loaded(self):
        return self.driver.current_url.endswith(self.PATH)


driver = FakeDriver()
LoginPage(driver).open().login("standard_user", "secret_sauce")
assert driver.actions[0] == ("open", "https://www.saucedemo.com/")
assert driver.actions[-1] == ("click", ("id", "login-button"))

Trying BasePage(driver) on its own raises TypeError, because an abstract class can't be created. That is abstraction enforced by the language.

Composition: a flow built from pages

Inheritance means "is a" (LoginPage is a BasePage). Composition means "has a": a checkout flow has several pages. Prefer composition for business flows.

classmethod and staticmethod

class User:
    def __init__(self, username, password, role="customer"):
        self.username, self.password, self.role = username, password, role

    @classmethod
    def from_dict(cls, data):                 # alternative constructor, e.g. from JSON
        return cls(data["username"], data["password"], data.get("role", "customer"))

    @staticmethod
    def is_strong(password):                  # utility; needs neither cls nor self
        return len(password) >= 8 and any(c.isdigit() for c in password)
"Explain the OOP concepts in your framework": a model answer

"Our framework uses the Page Object Model. Encapsulation: each page class keeps its locators private and exposes actions like login(), so a UI change means one fix in one place. Inheritance: every page extends a BasePage that holds the common driver actions and explicit waits. Abstraction: tests read like business steps, such as checkout.place_order(), and BasePage declares an abstract is_loaded() that every page must implement. Polymorphism: a driver factory returns Chrome, Firefox or a remote Grid driver, and the tests use them the same way. Each page also overrides is_loaded() with its own check."

Follow-ups: overloading vs overriding (Python has no true overloading: use default arguments; overriding is a child redefining a parent method). Abstract class vs interface (Python uses ABCs for both). Is-a vs has-a (inheritance vs composition).

Interview questions

How do you handle test data? External files (CSV, JSON, Excel) for data-driven tests; generated data for unique values; API or SQL setup for complex state. Secrets come from environment variables or a vault, never from the repo.

How do you manage multiple environments? A config file per environment, or one file with sections, chosen by an environment variable or a pytest command-line option, e.g. --env uat.

try/except/else/finally: when does each block run? try always; except on a matching error; else only if there was no error; finally always.

Write retry(func, attempts=3, delay=0.5, exceptions=(Exception,)). It calls func() and retries on the given exceptions. If every attempt fails, re-raise the last error. (Real use: an API call during a slow deployment. Never use it to hide a genuine bug.)

Show answer
import time

def retry(func, attempts=3, delay=0.5, exceptions=(Exception,)):
    for attempt in range(1, attempts + 1):
        try:
            return func()
        except exceptions:
            if attempt == attempts:
                raise
            time.sleep(delay)

calls = {"n": 0}
def flaky():
    calls["n"] += 1
    if calls["n"] < 3:
        raise ConnectionError("not yet")
    return "ok"

assert retry(flaky, delay=0) == "ok" and calls["n"] == 3
try:
    retry(lambda: 1 / 0, attempts=2, delay=0, exceptions=(ZeroDivisionError,))
    raise AssertionError("expected ZeroDivisionError")
except ZeroDivisionError:
    pass

def mask_email(email):
    if email is None:
        return None
    if "@" not in email:

    return f"{local[:1]}***@{domain}"

Parametrize: one test, many inputs

@pytest.mark.parametrize(
    "email, expected",
    [
        ("priya.nair@mail.com", "p***@mail.com"),
        ("a@b.co", "a***@b.co"),
        ("@mail.com", "***@mail.com"),          # edge case: empty local part

    ids=["normal", "short", "empty-local"],
)
def test_mask_email(email, expected):
    assert mask_email(email) == expected

Each row is reported as a separate test, e.g. test_mask_email[short]. This is pytest's data-driven testing.

Fixtures: setup and teardown done properly

A fixture prepares something a test needs. The test asks for it by naming it as a parameter. Code after yield is the teardown, and it runs even if the test fails.

Register your markers in pytest.ini; otherwise pytest warns about typos. xfail(strict=True) means "this is expected to fail because of a known bug". Once the bug is fixed and the test passes, the run fails, which reminds you to remove the marker.

Interview questions

What is a fixture? How is it different from setup/teardown methods? A fixture is a reusable function that provides a resource, injected by name, with a scope, and with teardown after yield. Unlike xUnit setUp methods, fixtures are modular, can depend on each other, and can be shared through conftest.py.

What is conftest.py? A file pytest loads automatically, holding fixtures and hooks shared by all tests in its folder tree.

How do you run only some tests? -k by name, -m by marker, by path, or --lf for the last failures.

skip vs xfail? skip doesn't run the test. xfail runs it and expects it to fail, reporting XFAIL, or XPASS if it unexpectedly passes.

pytest vs unittest? pytest uses plain asserts with detailed output, fixtures, parametrize, a large plugin ecosystem (xdist, allure, rerunfailures, html), and it can also run unittest tests.

Interview questions

git fetch vs git pull? fetch downloads without changing your branch; pull is fetch plus merge (or rebase).

merge vs rebase? merge keeps both histories and adds a merge commit. rebase replays your commits on top for a straight line. Don't rebase commits other people already have.

reset vs revert? reset moves the branch pointer and can discard commits (local use). revert creates a new commit that undoes an old one (safe on shared branches).

5. The test: tests/test_data_checks.py

from pathlib import Path

import pytest

CHECKS_DIR = Path(__file__).parent.parent / "checks"

# Checks that fail today because of defects already raised.
# strict=True: once a fix lands the check passes, pytest reports XPASS(strict)
# as a failure, and that reminds you to remove the entry from this list.
KNOWN_DEFECTS = {
    "orders_without_customer": "DEF-101: order 1015 points to customer 99",
    "items_without_order": "DEF-102: item 30 points to order 9999",
    "duplicate_emails": "DEF-103: customers 2 and 9 share an email",
    "missing_emails": "DEF-104: customer 5 has no email",
    "header_line_mismatch": "DEF-105: orders 1003, 1010, 1017",
    "duplicate_order_lines": "DEF-106: order 1003 has product 103 twice",
    "delivered_unpaid": "DEF-107: order 1007 delivered with no payment",
    "payment_mismatch": "DEF-108: order 1018 undercharged by 9",
    "defect_status_date_mismatch": "DEF-109: defect 16 closed with no date",
}


def load_checks():
    params = []
    for path in sorted(CHECKS_DIR.glob("*.sql")):
        name = path.stem
        marks = [pytest.mark.data]
        if name in KNOWN_DEFECTS:
            marks.append(pytest.mark.xfail(reason=KNOWN_DEFECTS[name], strict=True))
        params.append(pytest.param(path, id=name, marks=marks))
    return params


@pytest.mark.parametrize("check_file", load_checks())
def test_data_check(db, check_file):
    sql = check_file.read_text(encoding="utf-8")
    failing_rows = db.execute(sql).fetchall()
    assert failing_rows == [], f"{len(failing_rows)} failing row(s): {failing_rows[:10]}"
